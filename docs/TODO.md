# 后续迭代

- 特殊皮肤与多形态：终极皮肤、特殊模型／装备、额外 stack 层、技能及变形状态。例如女帝卡特琳娜的特殊匕首／形态行为仍需适配；问题并不限于“终极”稀有度。方向：帧线程监视 stack 顶层被游戏改写时按规则重应用，规则以数据表描述（形态链、附属对象、额外 stack 层），逐个皮肤在训练模式确认引擎行为后接入对应实现。
  - 元素使拉克丝已支持手动选择十种形态，训练模式抽查光、风、火及 Q/W/E/R，形态互切、原皮恢复和自建层释放通过；已有游戏层的兼容仍待适配。无需自然元素进度。
  - 其他终极皮肤（如脉冲火焰伊泽瑞尔、灵魂守卫乌迪尔、DJ 娑娜、枪炮女神厄运小姐）逐个在训练模式研究：形态是额外层、gear 还是等级驱动。确认后接入 `forms.rs` 与原生表，界面自动出现切换栏。
- 炫彩：目录与界面已支持，走普通 `apply`。待训练模式抽查若干英雄的炫彩模型、技能特效与恢复；原皮本身就是炫彩的玩家，恢复应回到该炫彩。
- 游戏更新后按 `ADAPTATION.md` 适配新构建，更新 `data/builds.json` 与随版本发布的目录。
- 接入已改为按运行时代码和英雄数据解析，不使用哈希白名单；离线诊断命令为 `cargo xtask check-build <EXE>`。构建间差异比较仍待实现。
- host 协议增加结构化错误码，替代 `skinlab-core/src/error.rs` 中的英文片段匹配。
- 改善接入失败后的重试。正常停止后已支持同局重新打开；恢复未完成时仍保留原会话，启动超时不自动重复加载。
- 第二阶段：在 Rust 控制端稳定后，评估把 host 并入 `skinlab-session`、把会话 DLL 改为 Rust cdylib；须先在 fixture 和训练模式完成同等验证。
- 按实际反馈修复英雄／皮肤兼容问题；不维护逐英雄测试台账。
